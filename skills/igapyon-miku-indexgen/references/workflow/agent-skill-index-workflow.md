# Agent Skill Index Workflow

Use this workflow when applying `miku-indexgen` to an Agent Skills package.

The goal is to place a generated `index.json` at the skill root so an installed
skill bundle can describe its own files to an agent before the agent reads
larger references or runtime artifacts.

## Recommended Shapes

### Single-Skill Package

For a repository or bundle that effectively owns one skill at:

```text
skills/<skill-name>/
```

generate:

```text
skills/<skill-name>/index.json
```

Treat this file as generated. Do not maintain it by hand.

### Multi-Skill Package

When a repository has a `skills/` directory containing multiple Agent Skill
directories, generate the index at the parent directory level:

```text
skills/index.json
```

Use `skills/` as the input directory. This gives the agent one generated
inventory for the full skill collection before it chooses which individual skill
directory to inspect.

Example:

```text
skills/
  index.json
  skill-a/
    SKILL.md
  skill-b/
    SKILL.md
```

For multi-skill packages, each individual skill may still keep its own curated
`references/INDEX.md` when it has detailed references. The parent
`skills/index.json` is the generated inventory of the collection.

## Why This Helps

Agent Skills often contain several kinds of files:

- `SKILL.md`
- curated references
- examples
- helper code
- bundled runtime artifacts
- generated or metadata files

A generated `index.json` lets an agent inspect the package or collection shape
first and then choose which files to read in full. The expected effect is fewer
unnecessary file reads and lower context size.

## Curated INDEX.md vs Generated index.json

Keep both when the skill has references.

- `index.json`
  - generated file inventory
  - useful for broad package overview
  - regenerated by `miku-indexgen`
- `references/INDEX.md`
  - curated guide
  - explains which reference to read for which question
  - maintained by humans or agent edits

In `references/INDEX.md`, explicitly mention that `../index.json` is the
generated file inventory.

In `SKILL.md`, include `index.json` in the References section as the generated
file inventory for the skill package.

## Maven + Ant Generation

When the repository already uses Maven conventions or wants a standard resource
generation command, use Maven Antrun in `generate-resources`.

Be very cautious with `pom.xml`. Creating or rewriting Maven build files is a
repository-level build change. Do not do it just because this skill has Maven
templates. Do it only when the user explicitly asks for Maven, Ant, `pom.xml`,
or resource-generation wiring and agrees to that build-file change.

If the user asks about the approach but has not agreed to edit `pom.xml`, explain
the Maven + Ant option and point to the templates instead of changing files.

Recommended command:

```bash
mvn generate-resources
```

Recommended behavior:

- run the bundled `miku-indexgen` jar
- use `skills/<skill-name>` as `--input-directory` for a single-skill package
- use `skills` as `--input-directory` for a multi-skill package
- write output directly to the selected input directory
- set a clear `--title`
- use `--include-ext md,mjs,json` unless the skill has a reason to include more

The Node.js runtime can be used in environments where Node.js is the available
backend. Keep Maven + Ant generation Java-based because Maven can run the jar
directly without requiring Node.js.

Important backend note:

- Java runtime: supports the Agent Skills index generation workflow, including
  parent-directory generation for multi-skill packages
- Node.js runtime: supports the same CLI help and option surface in the bundled
  runtime set, including parent-directory generation

Example Maven Antrun shape:

```xml
<java jar="${indexgen.jar}" fork="true" failonerror="true">
  <arg value="--input-directory" />
  <arg value="${skill.dir}" />
  <arg value="--title" />
  <arg value="igapyon-miku-indexgen Skill Index" />
  <arg value="--include-ext" />
  <arg value="md,mjs,json" />
</java>
```

Generating directly into the input directory is acceptable. Do not add
unnecessary staging unless a project-specific reason exists.

## Bundle Tests

When a generated `index.json` is part of the package, the release bundle test
should assert that it is included.

Single-skill package:

```js
assertIncludes(entries, "skills/<skill-name>/index.json");
```

Multi-skill package:

```js
assertIncludes(entries, "skills/index.json");
```

This protects installed bundles from losing the generated inventory.

## Update Discipline

Regenerate `index.json` after changing skill files that should be visible in the
inventory:

- `SKILL.md`
- reference documents
- examples
- helper code
- relevant metadata files

Do not manually patch the generated JSON. Rerun the configured generation
command instead.
