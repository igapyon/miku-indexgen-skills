# index.json Specification

This reference summarizes the `index.json` file generated by `miku-indexgen`.
Use it when a user asks about the structure, fields, formatting, or maintenance
rules of generated `index.json` files.

The upstream runtime remains the source of truth. This document records the
contract exposed by the bundled `miku-indexgen` runtime artifacts in this skill
package.

## Ownership

`index.json` is a generated artifact.

Do not maintain it by hand. When it is missing, stale, or needs different
options, rerun `miku-indexgen` with the intended CLI arguments.

## Output Location

By default, `index.json` is written under the input directory:

```bash
miku-indexgen --input-directory docs
```

This writes:

```text
docs/index.json
```

When `--output-directory <dir>` is specified, `index.json` is written under the
output directory instead:

```bash
miku-indexgen --input-directory docs --output-directory out
```

This writes:

```text
out/index.json
```

## Root Structure

Generated JSON uses a flat `files` array as the canonical structure.

Root-level fields:

- `title`: optional string, present when `--title <text>` is specified
- `generator`: optional object, omitted when `--no-generator` is specified
- `basePath`: string
- `files`: array of file entries

Example shape:

```json
{
 "title": "Docs Index",
 "generator": {
  "...": "..."
 },
 "basePath": "docs",
 "files": [
  {"name":"README.md","path":"README.md","ext":"md","dir":"","size":1234,"summary":"..."}
 ]
}
```

The exact contents of `generator` are runtime metadata. Do not depend on unknown
or undocumented `generator` subfields unless the upstream runtime documents
them.

## File Entries

Each `files[]` entry describes one indexed file.

Common fields:

- `name`: file name
- `path`: path relative to the generated index base
- `ext`: file extension without the leading dot
- `dir`: containing directory relative to the generated index base
- `size`: file size in bytes
- `title`: optional string, extracted from Markdown front matter
- `topics`: optional array, extracted from Markdown front matter
- `summary`: optional string

Optional fields are omitted when the runtime does not extract a value.

## Markdown Summary Extraction

For Markdown files, `summary` is extracted from the first heading or from the
leading body text.

If the file starts with Markdown front matter, that front matter is excluded
from `summary` extraction.

If front matter is absent, Markdown `title` and `topics` fields are omitted.
The first heading or leading body text may still produce `summary`.

Example without front matter:

```markdown
# Writing Guide

This document describes writing conventions.
```

Expected file entry behavior:

- `summary` may be `Writing Guide`
- `title` is omitted
- `topics` is omitted

Markdown front matter metadata is optional. `miku-indexgen` reads simple
`title` and `topics` fields:

```markdown
---
title: Writing Guide
topics:
  - writing
  - article
  - tone
---
```

When present, these may appear in the file entry as `title` and `topics`.

## JSON Summary Extraction

For JSON files, `summary` is omitted by default.

When `--json-summary-path <paths>` is specified, each path is treated as a JSON
Pointer. The runtime evaluates the comma-separated paths from left to right and
uses the first matching string value as `summary`.

Example:

```bash
miku-indexgen --input-directory docs --json-summary-path /title,/name
```

Another example:

```bash
miku-indexgen --input-directory references --json-summary-path /frontmatter/title,/metadata/title,/title
```

## Formatting

The root structure uses one-space indentation for compact readability.

Each `files` entry is written on one line. This is intentional: it makes
`rg` / `grep` results useful as file-level records.

Line breaks inside string values are escaped by JSON encoding, so one file entry
does not split across multiple physical lines because of source text line
breaks.

## Options That Affect index.json

- `--input-directory <dir>`: directory to scan
- `--output-directory <dir>`: directory to write `index.json`
- `--title <text>`: adds root-level `title`
- `--no-generator`: omits root-level `generator`
- `--json-summary-path <paths>`: extracts JSON summaries from JSON Pointer paths
- `--no-recursive`: disables recursive scanning
- `--no-overwrite`: skips writing when output already exists
- `--include-ext <exts>`: restricts included file extensions
- `--input-encoding <encoding>`: reads supported text files as `utf8` or `shift_jis`
- `--output-encoding <encoding>`: writes output as `utf8` or `shift_jis`

## Agent Guidance

When asked about `index.json`, answer from this reference first.

When asked to change `index.json`, do not edit the JSON directly. Instead:

1. identify the source directory
2. identify the output directory
3. identify required options
4. rerun `miku-indexgen`
5. inspect the generated file and report the output path
